# SocialSphere

Учебный проект (вариант 5) для лабораторной работы №6  
«Работа с веб-API браузера и асинхронными операциями».

## Что реализовано

- Интеграция с внешним сервисом `JSONPlaceholder` (`GET /posts`, `GET /posts/{id}/comments`, `POST /posts`)
- Асинхронная логика на `Promise`, `async/await`, `Fetch`
- Обработка JSON-ответов и ошибок сети/HTTP
- Кэш ленты в локальном хранилище (`LocalStorage`)
- Черновики постов с автосохранением (локальное и сессионное хранилище)
- Очередь отправки постов в оффлайне с автосинхронизацией при восстановлении сети
- Lazy-загрузка комментариев по нажатию на пост
- Индикаторы состояния сети, синхронизации и ошибок

## Проверка сценариев ЛР6

1. Запустите страницу и откройте DevTools → Network.
2. Проверьте загрузку ленты и комментариев с сервера.
3. Создайте пост онлайн и убедитесь, что он отправляется на сервер.
4. Отключите сеть (`Offline` в DevTools), создайте пост и проверьте:
   - пост остался в ленте;
   - счетчик очереди вырос;
   - после включения сети пост синхронизировался.
5. Откройте DevTools → Application:
   - `LocalStorage`: кэш ленты, очередь, черновик;
   - `SessionStorage`: текущий черновик и список видимых постов.

## Переменные окружения

Создайте `.env` по шаблону:

```bash
cp .env.example .env
```

Для `JSONPlaceholder` ключ не нужен.  
Для реальных сервисов не храните секретные ключи в клиентском JavaScript: используйте прокси-сервер, ограничения ключей и OAuth.

## Docker

Запуск через Docker Compose:

```bash
docker compose up --build -d
```

Приложение будет доступно на `http://localhost:8080`.

Полезные команды:

```bash
docker compose ps
docker compose logs -f
docker compose down
```
